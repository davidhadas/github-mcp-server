# ExtendedReverseProxy - Plan Summary

## Overview

This document summarizes the complete plan for building the `extendedreverseproxy` package in `pkg/extendedreverseproxy`.

## What We're Building

An HTTP reverse proxy that extends `net/http/httputil.ReverseProxy` to support **detached request/response flows** for Kubernetes sidecar scenarios.

### Key Capabilities

1. **Scenario 1 (Normal Forward)**: Standard reverse proxy behavior
   - Client → Sidecar → App
   - Client ← Sidecar ← App (streamed directly)

2. **Scenario 2 (Detach and Resume)**: Deferred response delivery
   - Type A: Client → Sidecar → App (starts), Client ← Sidecar (interim 401/202)
   - Type B: Client → Sidecar (lookup), Client ← Sidecar ← App (streamed)

## Core Design Principles

1. **Token/Key Management**: Correlation keys are provided by the caller (sidecar), not generated by the proxy
2. **Context Independence**: Detached upstream requests use independent contexts to survive Type A completion
3. **No Buffering**: Upstream responses stream directly to Type B without buffering the full body
4. **Standard Library Alignment**: Follow `httputil.ReverseProxy` patterns for logging, error handling, and configuration

## Key Types

### Request Classification
- `RequestKind`: Enum for Forward (Type A) vs Resume (Type B)
- `InboundRequest`: Classified request with correlation key
- `UpstreamRequest`: Request being prepared for upstream

### Proxy Actions
- `ForwardNow`: Stream upstream response to current request
- `RespondNow`: Send local response without upstream
- `DetachAndWait`: Send interim response, keep upstream alive

### Core Interfaces
- `PendingExchange`: Represents a detached upstream request
- `PendingStore`: Manages pending exchanges with TTL
- `BufferPool`: Provides byte buffers for streaming

### Hook Functions
- `ClassifyFunc`: Determine request type and correlation key
- `RewriteFunc`: Prepare upstream request
- `DecideFunc`: Choose proxy action
- `ModifyResponseFunc`: Modify response before streaming
- `ErrorHandlerFunc`: Handle errors

## Implementation Flow

### Type A Request (Forward or Detach)
1. Classify request → Type A with key K
2. Prepare upstream request (clone, remove hop-by-hop headers)
3. Rewrite upstream request (set URL, headers)
4. Decide action (ForwardNow, RespondNow, or DetachAndWait)
5. Execute action:
   - **ForwardNow**: Do upstream request, stream response
   - **RespondNow**: Send local response immediately
   - **DetachAndWait**: Start upstream in background, store PendingExchange, send interim response

### Type B Request (Resume)
1. Classify request → Type B with key K
2. Lookup PendingExchange by key K
3. Wait for upstream response (with timeout)
4. Stream upstream response to Type B client
5. Cleanup pending exchange

## Critical Implementation Details

### Context Management
```go
// WRONG - upstream cancels when Type A completes
upstreamCtx := typeARequest.Context()

// CORRECT - upstream survives Type A completion
upstreamCtx, cancel := context.WithTimeout(context.Background(), timeout)
```

### Header Handling
- Copy headers preserving multi-value headers
- Remove hop-by-hop headers (Connection, Keep-Alive, etc.)
- Parse Connection header and remove listed headers
- Handle trailers correctly

### Streaming
- Use `io.Copy` with periodic flushing
- Support `http.Flusher` for streaming responses
- Use buffer pool to minimize allocations
- No full-body buffering

### Store Management
- In-memory map with mutex protection
- TTL/expiration per entry
- Background cleanup goroutine
- Cleanup on success, failure, or expiration

## Configuration Example

```go
proxy := &extendedreverseproxy.ExtendedReverseProxy{
    Classify: func(r *http.Request) (extendedreverseproxy.InboundRequest, error) {
        if key := r.Header.Get("X-Resume-Key"); key != "" {
            return extendedreverseproxy.InboundRequest{
                Kind: extendedreverseproxy.RequestKindResume,
                In:   r,
                Key:  key,
            }, nil
        }
        return extendedreverseproxy.InboundRequest{
            Kind: extendedreverseproxy.RequestKindForward,
            In:   r,
            Key:  generateSecureKey(),
        }, nil
    },
    
    Rewrite: func(ur *extendedreverseproxy.UpstreamRequest) {
        ur.Out.URL.Scheme = "http"
        ur.Out.URL.Host = "127.0.0.1:8080"
        ur.Out.Host = "127.0.0.1:8080"
    },
    
    Decide: func(ur *extendedreverseproxy.UpstreamRequest) (extendedreverseproxy.ProxyAction, error) {
        if needsDetach(ur.In) {
            return extendedreverseproxy.DetachAndWait{
                InterimStatusCode: http.StatusUnauthorized,
                InterimHeader:     http.Header{"X-Resume-Key": []string{ur.Key}},
                InterimBody:       []byte("Authentication required"),
            }, nil
        }
        return extendedreverseproxy.ForwardNow{}, nil
    },
    
    Transport:     http.DefaultTransport,
    FlushInterval: 100 * time.Millisecond,
    Store:         extendedreverseproxy.NewMemoryStore(),
    Timeout:       5 * time.Minute,
}

http.Handle("/", proxy)
```

## Key Decisions Made

1. **Package name**: `extendedreverseproxy` (lowercase, Go convention)
2. **Token handling**: Caller-provided correlation keys, not generated by proxy
3. **Store type**: In-memory only (persistent stores can be added later)
4. **Logging**: Use `*log.Logger` like `httputil.ReverseProxy`
5. **Testing**: Use `httptest.Server` for realistic integration tests
6. **Error handling**: Follow `httputil.ReverseProxy` patterns with `ErrorHandler` hook
