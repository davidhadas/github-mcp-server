# ExtendedReverseProxy Architecture Plan

## Overview

The `extendedreverseproxy` package provides an HTTP reverse proxy that supports detached request/response flows, enabling a sidecar to:
1. Forward requests normally (Scenario 1)
2. Return intermediate responses while keeping upstream requests alive, then bind the upstream response to a later resume request (Scenario 2)

This architecture is based on `net/http/httputil.ReverseProxy` but breaks the assumption that upstream responses must be written to the same downstream `ResponseWriter`.

## Core Types

### Request Classification

```go
type RequestKind int

const (
    RequestKindForward RequestKind = iota  // Type A: normal request
    RequestKindResume                       // Type B: resume request
)

type InboundRequest struct {
    Kind  RequestKind
    In    *http.Request
    Key   string  // Correlation key provided by caller
}
```

**Design Note**: The correlation key is provided by the caller (sidecar), not generated by the proxy. This keeps token generation and security policy outside the proxy's responsibility.

### Upstream Request

```go
type UpstreamRequest struct {
    In  *http.Request   // Original inbound request
    Out *http.Request   // Prepared upstream request
    Key string          // Correlation key for this exchange
}
```

### Proxy Actions

```go
type ProxyAction interface {
    isProxyAction()
}

type ForwardNow struct{}        // Stream upstream response to current request
type RespondNow struct {        // Send local response, don't wait for upstream
    StatusCode int
    Header     http.Header
    Body       []byte
}
type DetachAndWait struct {     // Send interim response, keep upstream alive
    InterimStatusCode int
    InterimHeader     http.Header
    InterimBody       []byte
}
```

## Key Interfaces

### PendingExchange

Represents a detached upstream request that can be resumed later:

```go
type PendingExchange interface {
    Key() string
    WaitResponse(ctx context.Context) (*http.Response, error)
    Cancel(err error)
}
```

**Implementation**: 
- Wraps an in-flight `http.Client.Do()` call
- Stores the eventual `*http.Response` 
- Provides synchronization via channel
- Manages cancellation context

### PendingStore

Manages pending exchanges with TTL:

```go
type PendingStore interface {
    Put(key string, exchange PendingExchange, expiresAt time.Time) error
    Get(key string) (PendingExchange, bool)
    Delete(key string) error
}
```

**Implementation**:
- In-memory map with mutex protection
- Background cleanup goroutine
- Expiration tracking per entry

## Hook Functions

### ClassifyFunc

```go
type ClassifyFunc func(*http.Request) (InboundRequest, error)
```

**Purpose**: Caller determines if request is Type A or Type B and provides correlation key.

**Example**:
```go
func classify(r *http.Request) (InboundRequest, error) {
    if key := r.Header.Get("X-Resume-Key"); key != "" {
        return InboundRequest{Kind: RequestKindResume, In: r, Key: key}, nil
    }
    return InboundRequest{Kind: RequestKindForward, In: r, Key: generateKey()}, nil
}
```

### RewriteFunc

```go
type RewriteFunc func(*UpstreamRequest)
```

**Purpose**: Prepare the upstream request (similar to `httputil.ProxyRequest.Rewrite`).

**Responsibilities**:
- Set target URL
- Modify headers (X-Forwarded-*, etc.)
- Adjust request for upstream server

### DecideFunc

```go
type DecideFunc func(*UpstreamRequest) (ProxyAction, error)
```

**Purpose**: Decide how to handle this request after upstream is prepared.

**Returns**:
- `ForwardNow`: Normal proxy (Scenario 1)
- `RespondNow`: Local response only
- `DetachAndWait`: Detach flow (Scenario 2)

### ErrorHandlerFunc

```go
type ErrorHandlerFunc func(http.ResponseWriter, *http.Request, error)
```

**Purpose**: Handle errors during proxy operation (similar to `httputil.ReverseProxy.ErrorHandler`).

## Main Proxy Type

```go
type ExtendedReverseProxy struct {
    // Required hooks
    Classify ClassifyFunc
    Rewrite  RewriteFunc
    Decide   DecideFunc
    
    // Optional hooks
    ModifyResponse func(*http.Response) error
    ErrorHandler   ErrorHandlerFunc
    
    // Transport configuration
    Transport     http.RoundTripper
    FlushInterval time.Duration
    BufferPool    BufferPool
    
    // Logging
    ErrorLog *log.Logger
    
    // Detached exchange management
    Store   PendingStore
    Timeout time.Duration  // TTL for pending exchanges
    
    // Internal state
    cleanupOnce sync.Once
    cleanupDone chan struct{}
}
```

## Core Flows

### Scenario 1: Normal Forward (ForwardNow)

```
Client -> Sidecar -> App
       <- Sidecar <- App (streamed directly)
```

1. Classify request as Type A
2. Rewrite upstream request
3. Decide returns `ForwardNow`
4. Start upstream request
5. Stream response directly to client

### Scenario 2: Detach and Resume (DetachAndWait)

```
Type A:
Client -> Sidecar -> App (starts)
       <- Sidecar (interim 401/202)
                    App (continues)

Type B:
Client -> Sidecar (lookup pending)
       <- Sidecar <- App (streamed)
```

1. **Type A Phase**:
   - Classify as Type A with key K
   - Rewrite upstream request
   - Decide returns `DetachAndWait`
   - Start upstream with detached context
   - Store PendingExchange with key K
   - Send interim response to client
   
2. **Type B Phase**:
   - Classify as Type B with key K
   - Lookup PendingExchange by key K
   - Wait for upstream response
   - Stream response to Type B client
   - Cleanup pending exchange

## Context Management

**Critical Design Point**: Upstream requests in Scenario 2 must NOT use the Type A request context.

```go
// WRONG - upstream cancels when Type A completes
upstreamCtx := typeARequest.Context()

// CORRECT - upstream survives Type A completion
upstreamCtx, cancel := context.WithTimeout(context.Background(), proxy.Timeout)
```

The proxy creates independent contexts for detached upstream requests.

## Header Handling

Adapted from `httputil.ReverseProxy`:

1. **Copy headers** preserving multi-value headers
2. **Remove hop-by-hop headers**:
   - Connection
   - Keep-Alive
   - Proxy-Authenticate
   - Proxy-Authorization
   - Te
   - Trailers
   - Transfer-Encoding
   - Upgrade
3. **Parse Connection header** and remove listed headers
4. **Handle trailers** correctly in both directions
5. **Preserve Content-Length** when valid

## Streaming

Response streaming without buffering:

```go
func streamResponse(w http.ResponseWriter, resp *http.Response, flushInterval time.Duration) error {
    // Copy headers
    copyHeaders(w.Header(), resp.Header)
    removeHopByHopHeaders(w.Header())
    
    // Announce trailers
    if len(resp.Trailer) > 0 {
        trailerKeys := make([]string, 0, len(resp.Trailer))
        for k := range resp.Trailer {
            trailerKeys = append(trailerKeys, k)
        }
        w.Header().Add("Trailer", strings.Join(trailerKeys, ", "))
    }
    
    // Write status
    w.WriteHeader(resp.StatusCode)
    
    // Stream body with periodic flushing
    err := copyWithFlush(w, resp.Body, flushInterval)
    
    // Copy trailers
    copyHeaders(w.Header(), resp.Trailer)
    
    return err
}
```

## Error Handling

Errors can occur at multiple points:

1. **Classification error**: Return 400 Bad Request
2. **Upstream dial error**: Call ErrorHandler
3. **Upstream timeout**: Call ErrorHandler  
4. **Upstream read error**: Log and close connection
5. **Resume key not found**: Return 404 Not Found
6. **Resume key expired**: Return 410 Gone

Default ErrorHandler logs and returns 502 Bad Gateway.

## Cleanup and Resource Management

### Pending Exchange Cleanup

Cleanup occurs when:
- Type B successfully retrieves response
- Upstream request fails
- TTL expires
- Proxy shutdown

### Background Cleanup Goroutine

```go
func (p *ExtendedReverseProxy) startCleanup() {
    p.cleanupOnce.Do(func() {
        p.cleanupDone = make(chan struct{})
        go p.cleanupLoop()
    })
}

func (p *ExtendedReverseProxy) cleanupLoop() {
    ticker := time.NewTicker(time.Minute)
    defer ticker.Stop()
    
    for {
        select {
        case <-ticker.C:
            p.Store.CleanupExpired()
        case <-p.cleanupDone:
            return
        }
    }
}
```

### Example Test Structure

```go
func TestScenario1_NormalForward(t *testing.T) {
    // Create test upstream server
    upstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.WriteHeader(http.StatusOK)
        w.Write([]byte("upstream response"))
    }))
    defer upstream.Close()
    
    // Create proxy
    proxy := &ExtendedReverseProxy{
        Classify: func(r *http.Request) (InboundRequest, error) {
            return InboundRequest{Kind: RequestKindForward, In: r, Key: "test"}, nil
        },
        Rewrite: func(ur *UpstreamRequest) {
            ur.Out.URL, _ = url.Parse(upstream.URL)
        },
        Decide: func(ur *UpstreamRequest) (ProxyAction, error) {
            return ForwardNow{}, nil
        },
        Transport: http.DefaultTransport,
        Store:     NewMemoryStore(),
    }
    
    // Test request
    req := httptest.NewRequest("GET", "/test", nil)
    rec := httptest.NewRecorder()
    
    proxy.ServeHTTP(rec, req)
    
    // Verify response
    if rec.Code != http.StatusOK {
        t.Errorf("expected 200, got %d", rec.Code)
    }
}
```

## Key Design Decisions

### 1. Token/Key Management
**Decision**: Correlation keys are provided by the caller, not generated by the proxy.
**Rationale**: Security policy (token generation, entropy) should be controlled by the sidecar, not the proxy library.

### 2. Context Lifecycle
**Decision**: Detached upstream requests use independent contexts.
**Rationale**: Upstream work must survive Type A completion in Scenario 2.

### 3. Store Interface
**Decision**: Provide interface with in-memory implementation only.
**Rationale**: Simplicity. Persistent stores can be added later if needed.

### 4. Error Handling
**Decision**: Follow `httputil.ReverseProxy` pattern with ErrorHandler hook.
**Rationale**: Consistency with standard library, flexibility for callers.

### 5. Logging
**Decision**: Use `*log.Logger` like `httputil.ReverseProxy`.
**Rationale**: Simple, standard, no external dependencies.

## Compatibility Notes

- Requires Go 1.20+ (for `http.ResponseController` if needed)
- No external dependencies beyond `golang.org/x/net/http/httpguts` (same as `httputil`)
- Thread-safe for concurrent requests
- Safe for use with HTTP/1.1 and HTTP/2
